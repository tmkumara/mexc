# Private Telegram structure review

This bot serves the Phase 2.9 historical review queue without starting the
signal bot or accessing MEXC. It starts only with the explicit `bot`
subcommand. Use a separate Telegram bot token. The adapter accepts commands
and inline buttons only in private chats from allowlisted user IDs.

## Local setup

From the repository root in the project's Python environment, install the
existing dependencies and Pillow, which turns the local chart renderer's
output into Telegram photos.

```powershell
python -m pip install -r requirements.txt Pillow
```

Create a dedicated review bot in Telegram with BotFather. In PowerShell 7, set
its token without putting the token in command history or printing it.

```powershell
$env:MEXC_REVIEW_TELEGRAM_BOT_TOKEN = Read-Host 'Review bot token' -MaskInput
```

To find your numeric Telegram user ID, send your new bot a private `/start`
message before launching the review process, then run the following once.
It prints only numeric sender IDs from private messages. Allowlist only the
ID you verified as yours.

```powershell
try {
    $uri = 'https://api.telegram.org/bot{0}/getUpdates' -f $env:MEXC_REVIEW_TELEGRAM_BOT_TOKEN
    $response = Invoke-RestMethod -Uri $uri -ErrorAction Stop
    $response.result | ForEach-Object { $_.message } |
        Where-Object { $_.chat.type -eq 'private' } |
        ForEach-Object { $_.from.id } | Sort-Object -Unique
} catch {
    Write-Error 'Could not retrieve the ID. Check that the token is set and no poller is running.'
} finally {
    Remove-Variable uri,response -ErrorAction SilentlyContinue
}
$env:MEXC_REVIEW_TELEGRAM_ALLOWED_USER_IDS = Read-Host 'Authorized numeric ID or comma-separated IDs'
```

You can instead use the repository's ignored local `.env` file. Keep its
contents private.

| Variable | Meaning |
|---|---|
| `MEXC_REVIEW_TELEGRAM_BOT_TOKEN` | Dedicated review bot token. |
| `MEXC_REVIEW_TELEGRAM_ALLOWED_USER_IDS` | Comma- or whitespace-separated numeric user IDs. |
| `MEXC_REVIEW_STORAGE_PATH` | Optional SQLite path. Defaults to `strong_choch_results/phase_2_10/review.sqlite3`. |
| `MEXC_REVIEW_QUEUE_PATH` | Optional prepared CSV. The PNG directory and chart manifest must be beside it. |

## Prepare and run

Phase 2.10 already contains the prepared queue and paired PNGs. To reproduce
them from the Phase 2.9 queue, use an unused directory and set the queue
variable to the new CSV. The source files are read-only.

```powershell
python -m research.strong_choch.review prepare --output strong_choch_results/phase_2_10_rebuild
# Start only when the token and authorized IDs are configured.
python -m research.strong_choch.review bot
```

Send `/start`, then `/next` in your private chat. `/start` shows your last
opened case since review progress and navigation persist. Use `/case <id>`
to reopen it or `/next` to continue. Stop the process with **Ctrl+C**. To
resume, start the same command with the same SQLite path. No queue is sent on
startup. Run just one poller per bot token.

Each photo is a frozen/shadow pair generated by replaying only through the
reviewed close. The audit line marks that final candle. Pivot origin and
confirmation are drawn separately. View Details shows the first usable close,
the structural leg, and the recorded decision context. There is no outcome
chart in this workflow.

| Action | Meaning |
|---|---|
| Valid CHoCH | A genuine external structural reversal. |
| Not CHoCH | The candle does not support external CHoCH. This does not classify its other structural role. |
| Valid BOS | A valid continuation break. |
| Ordinary Break | A local break without a major external change. |
| Ambiguous | Available evidence is insufficient. |

`/skip` navigates without assigning a label. Reopening a case and selecting a
different label records a correction. `/undo` restores your previous label
while preserving notes. Change notes with `/reason <case-id> <text>`, or clear
them with `/reason <case-id> --clear`. Per-reviewer records are independent.
Stale buttons require reopening the case. When a network error follows a
submission, reopen the case to see the persisted judgment before retrying.

## Export and interpret

```powershell
python -m research.strong_choch.review export --output strong_choch_results/phase_2_10/exports/review_01
```

Choose a new export directory each time. This command works with the poller
stopped, and generates effective decisions, append-only history, per-detector
CHoCH accuracy, and a summary. Keep the database and exports private. Notes
that start with spreadsheet formula characters are escaped in CSV. SQLite
retains the original text.

Only explicit human labels contribute. Conflicting human labels are surfaced
and excluded from consensus metrics. Unreviewed and ambiguous cases are
excluded. The Phase 2.6 minimum of two adjudicated positives and two negatives
per class applies before precision or recall is reported. Strong
classification disagreements are listed separately. The available labels
cannot adjudicate Strong correctness. The review set is enriched for detector
differences, so measured agreement describes this review set.
